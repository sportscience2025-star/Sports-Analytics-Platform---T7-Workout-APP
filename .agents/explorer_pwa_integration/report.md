## 1. Executive Summary

The project currently maintains a monolithic file `js/knowledge-base.js` (3,407 lines, 161 scientific sources) that populates `window.App.scientificSources` and `window.ScientificKnowledgeBase`. To fulfill the requirements of Task 1 (scaling from 161 to 250+ peer-reviewed studies across 7 thematic disciplines) while strictly adhering to project Single Responsibility guidelines (as established in `js/data.js`, `js/parser.js`, and `js/logic.js`), the database must be decomposed into 7 thematic modular files under `js/data/sources/` aggregated by an entry point `js/data/sources/index.js`.

### Key Findings & Actionable Highlights:
1. **Current Cache Version**: The repository is currently on cache version `t7-workout-v76` (in both `sw.js` and `test_check.py`). In accordance with PWA safety guidelines, adding new assets and modifying scripts requires bumping the cache version from `t7-workout-v76` to `t7-workout-v77` (rather than the placeholder v68 -> v69 from the dispatch prompt).
2. **Dual-Environment Architecture**: The application operates without a client-side bundler or native ES module loader in production. All browser scripts are executed as classic IIFEs sequentially loaded via `<script>` tags in `index.html`. For Node.js test runners (`tests/test_periodization_stress.js`, `test_new_profiles.js`, `test_adversarial_challenger.js`, `test_adversarial_scientific_hub.js`), the modular aggregators must include dynamic file loading (`fs.readFileSync` + `eval`) following the identical pattern found in `js/data.js` and `js/parser.js`.
3. **Backward Compatibility Facade**: Four major test files directly load `js/knowledge-base.js`. To prevent breaking regressions without requiring modifications to legacy test harnesses, `js/knowledge-base.js` should be retained as a lightweight orchestrator facade that delegates to `js/data/sources/index.js`.
4. **Service Worker Pre-caching**: `sw.js` uses `cache.addAll(CORE_ASSETS)`. A single 404 on any URL in `CORE_ASSETS` causes the entire Service Worker install to fail. Therefore, all 8 new files in `js/data/sources/` must be registered in `CORE_ASSETS` and verified to exist on disk.

## 3. Modular Architecture Design

### 3.1 File Hierarchy
All scientific data will be relocated into the directory `js/data/sources/`:

```
js/data/sources/
├── atletica.js             # Sources for "Atletica Leggera"
├── sollevamento-pesi.js    # Sources for "Sollevamento Pesi"
├── fisiologia.js           # Sources for "Fisiologia"
├── vbt.js                  # Sources for "VBT"
├── biomeccanica.js         # Sources for "Biomeccanica"
├── clinico.js              # Sources for "Clinico"
├── sport-squadra.js        # Sources for "Sport di Squadra"
└── index.js                # Aggregator entry point
```

In addition, `js/knowledge-base.js` is retained as a root orchestrator/backward-compatibility facade.

### 3.2 Individual Thematic File Specification
Each file under `js/data/sources/` encapsulates the sources for exactly one thematic area and attaches them to `window.App.Sources.<camelCaseName>`.

Standard structure for each thematic file (e.g. `js/data/sources/atletica.js`):

```javascript
/**
 * js/data/sources/atletica.js
 * Scientific Sources Database — Atletica Leggera (Track & Field)
 * Sprint mechanics, acceleration, maximum velocity, hurdle kinematics, jump biomechanics.
 */
(function () {
    'use strict';

    const root = typeof window !== 'undefined' ? window : (typeof global !== 'undefined' ? global : globalThis);
    root.window = root.window || root;
    root.window.App = root.window.App || {};
    root.window.App.Sources = root.window.App.Sources || {};

    root.window.App.Sources.atletica = [
        // Array of source objects with area: "Atletica Leggera"
    ];

    if (typeof module !== 'undefined' && module.exports) {
        module.exports = root.window.App.Sources.atletica;
    }
})();
```

#### Mapping of Thematic Files to `window.App.Sources` Keys:
1. `atletica.js` $\rightarrow$ `root.window.App.Sources.atletica` (Area: `"Atletica Leggera"`)
2. `sollevamento-pesi.js` $\rightarrow$ `root.window.App.Sources.sollevamentoPesi` (Area: `"Sollevamento Pesi"`)
3. `fisiologia.js` $\rightarrow$ `root.window.App.Sources.fisiologia` (Area: `"Fisiologia"`)
4. `vbt.js` $\rightarrow$ `root.window.App.Sources.vbt` (Area: `"VBT"`)
5. `biomeccanica.js` $\rightarrow$ `root.window.App.Sources.biomeccanica` (Area: `"Biomeccanica"`)
6. `clinico.js` $\rightarrow$ `root.window.App.Sources.clinico` (Area: `"Clinico"`)
7. `sport-squadra.js` $\rightarrow$ `root.window.App.Sources.sportSquadra` (Area: `"Sport di Squadra"`)

### 3.3 Aggregator Entry Point (`js/data/sources/index.js`)
`js/data/sources/index.js` fulfills two responsibilities:
1. **Node.js Environment**: If `typeof require !== 'undefined'`, dynamically finds and evaluates the 7 thematic files in order.
2. **Browser & Universal Environment**: Combines the 7 arrays into a single unified array, guarantees deduplication by `id`, and assigns:
   - `window.App.scientificSources = aggregated;`
   - `window.ScientificKnowledgeBase = aggregated;`
   - Helper methods: `window.App.getScientificSources()` and `window.App.getScientificSourcesByArea(area)`.

```javascript
/**
 * js/data/sources/index.js
 * Root Aggregator & Entry Point for Scientific Sources Database.
 * Combines thematic modules into window.App.scientificSources and window.ScientificKnowledgeBase.
 */
(function () {
    'use strict';

    const root = typeof window !== 'undefined' ? window : (typeof global !== 'undefined' ? global : globalThis);
    root.window = root.window || root;
    root.window.App = root.window.App || {};
    root.window.App.Sources = root.window.App.Sources || {};

    // Support Node.js test runners (eval / loadModule)
    if (typeof require !== 'undefined') {
        const fs = require('fs');
        const path = require('path');
        const baseDir = typeof __dirname !== 'undefined' ? __dirname : '.';
        const candidates = [
            path.join(baseDir, 'sources'),
            path.join(baseDir, 'js', 'data', 'sources'),
            path.join(baseDir, '..', 'js', 'data', 'sources'),
            path.join(baseDir, 'data', 'sources'),
            'js/data/sources',
            'data/sources'
        ];
        let sourcesDir = null;
        for (const c of candidates) {
            try {
                if (fs.existsSync(path.join(c, 'atletica.js'))) {
                    sourcesDir = c;
                    break;
                }
            } catch (e) {}
        }
        if (sourcesDir) {
            const files = [
                'atletica.js',
                'sollevamento-pesi.js',
                'fisiologia.js',
                'vbt.js',
                'biomeccanica.js',
                'clinico.js',
                'sport-squadra.js'
            ];
            for (const f of files) {
                const p = path.join(sourcesDir, f);
                try {
                    if (fs.existsSync(p)) {
                        const code = fs.readFileSync(p, 'utf8');
                        eval(code);
                    }
                } catch (e) {
                    console.error('[Sources Loader] Error loading', p, e);
                }
            }
        }
    }

    const s = root.window.App.Sources;
    const aggregated = [
        ...(s.atletica || []),
        ...(s.sollevamentoPesi || []),
        ...(s.fisiologia || []),
        ...(s.vbt || []),
        ...(s.biomeccanica || []),
        ...(s.clinico || []),
        ...(s.sportSquadra || [])
    ];

    // Expose primary global APIs
    root.window.App.scientificSources = aggregated;
    root.window.ScientificKnowledgeBase = aggregated;

    root.window.App.getScientificSources = function () {
        return root.window.App.scientificSources;
    };

    root.window.App.getScientificSourcesByArea = function (area) {
        if (!area || area === 'Tutti') return root.window.App.scientificSources;
        return root.window.App.scientificSources.filter(item => item.area === area);
    };

    if (typeof module !== 'undefined' && module.exports) {
        module.exports = aggregated;
    }
})();
```

### 3.4 Root Backward-Compatibility Facade (`js/knowledge-base.js`)
To ensure zero breaking changes across existing test harnesses:

```javascript
/**
 * js/knowledge-base.js
 * Backward Compatibility Facade & Orchestrator for Scientific Knowledge Base.
 * Delegates to js/data/sources/index.js.
 */
(function () {
    'use strict';

    const root = typeof window !== 'undefined' ? window : (typeof global !== 'undefined' ? global : globalThis);
    root.window = root.window || root;
    root.window.App = root.window.App || {};

    if (typeof require !== 'undefined') {
        const fs = require('fs');
        const path = require('path');
        const baseDir = typeof __dirname !== 'undefined' ? __dirname : '.';
        const candidates = [
            path.join(baseDir, 'js', 'data', 'sources', 'index.js'),
            path.join(baseDir, 'data', 'sources', 'index.js'),
            path.join(baseDir, '..', 'js', 'data', 'sources', 'index.js'),

            try {
                if (fs.existsSync(c)) {

                    break;
                }
            } catch (e) {}
        }
    }

    root.window.ScientificKnowledgeBase = root.window.App.scientificSources || [];
})();
```

## 4. Browser Environment Loading Strategy (`index.html`)

### 4.1 Evaluation of Loading Mechanisms
1. **Dynamic Script Loading (`document.createElement('script')`)**: Rejected.
   - Scripts loaded dynamically execute asynchronously by default.
   - PWA initial render could trigger `js/logic.js` or `js/ui.js` before the asynchronous source files complete execution, producing race conditions or empty data in `ScientificHub`.
2. **Standard Static `<script>` Tags**: Selected.
   - Standard browser execution guarantees synchronous, top-to-bottom execution.
   - Service Worker pre-caching matches static declaration.
   - Follows the identical, established pattern of `js/data/`, `js/parser/`, `js/logic/`, `js/analysis/`, and `js/ui/`.

### 4.2 Exact Script Placement & Order in `index.html`

In `index.html`, replace line 145 (`<script src="js/knowledge-base.js"></script>`) with the 8 modular source scripts, followed by the backward-compatibility facade:

**Order Rationale**:

- The 7 thematic scripts load first, populating `window.App.Sources.<area>`.
- `js/data/sources/index.js` loads next, aggregating all 7 into `window.App.scientificSources`.
- `js/knowledge-base.js` loads last as an idempotent safety wrapper.
