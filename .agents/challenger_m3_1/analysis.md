## 1. Executive Summary

Empirical testing was conducted to verify **Requirement R1 (Encoder ID Auto-Parsing)**. A test suite comprising 20 distinct scenarios—spanning exact specification examples, null/empty inputs, generic fallback tokens, special characters, and multi-word names with underscores—was executed.

### Key Findings:
1. **R1 Core Compliance**: All explicit R1 test cases (`Tommaso_mhkuhpch00134m`, `Mario_Rossi_mhkuhpch00134m`, `Tommaso_vbt01`, `encoder_123456`) successfully pass. Valid athlete names are cleanly extracted, and generic device tokens correctly fall back to `"Encoder"`.
2. **Graceful Fallback**: Empty strings, whitespace, null, undefined, and non-string inputs gracefully fall back to `"Encoder"`.
3. **Adversarial Failure Modes Identified**:
   - **Surname Truncation Bug**: Multi-word athlete names formatted with underscores but without a device token (e.g. `Mario_Rossi`) have their final surname truncated (`"Mario"`), leading to data loss.
   - **Tautological Regex Logic**: Line 83 of `js/parser.js` contains a redundant boolean check (`|| parts.length > 1`) that renders token verification dead code.
   - **Case Distortion on Compound/Special Characters**: Hyphenated or special-character names (e.g. `Anna-Maria` or `Tommaso@Gym`) undergo unwanted lowercasing (producing `Anna-maria` and `Tommaso@gym`).

## 3. Detailed Analysis of Failure Modes & Vulnerabilities

### Challenge 1: Surname Truncation in Underscore-Formatted Names (High Impact)
- **Code Location**: `js/parser.js:63-98`
- **Mechanism**:
  1. `isEncodedId("Mario_Rossi")` evaluates `/^.+_[a-z0-9]{3,}$/i.test("Mario_Rossi")`. Since `"Rossi"` matches `[a-z0-9]{3,}`, `isEncodedId` returns `true`.
  2. `extractReadableName("Mario_Rossi")` splits the string into `["Mario", "Rossi"]`.
  3. Inside `extractReadableName`, line 83 evaluates: `if (/^[a-z0-9]{3,}$/i.test(lastPart) || parts.length > 1)`.
  4. Because `parts.length > 1` is always true when `parts.length > 1`, `nameParts` is set to `parts.slice(0, -1)`, stripping `"Rossi"`.
- **Result**: Output is `"Mario"` instead of `"Mario Rossi"`.
- **Mitigation**: Device hex tokens follow specific patterns (e.g., lowercase hexadecimal or alphanumeric strings of length >= 5 or mixed digits/letters). The check should specifically target random hash tokens rather than standard English/Italian alphabetic words.

### Challenge 2: Tautological Logic on Line 83 (Medium Impact)
- **Code Snippet**:
  ```javascript
  if (parts.length > 1) {
      const lastPart = parts[parts.length - 1];
      if (/^[a-z0-9]{3,}$/i.test(lastPart) || parts.length > 1) { // <--- Redundant || parts.length > 1
          nameParts = parts.slice(0, -1);
      }
  }
  ```
- **Mechanism**: The second part of the logical OR (`|| parts.length > 1`) is evaluated inside an `if` block that already required `parts.length > 1`. Therefore, the regex check `/^[a-z0-9]{3,}$/i.test(lastPart)` is completely bypassed and ignored.
- **Mitigation**: Remove `|| parts.length > 1` so that the regex token inspection is actually executed.
