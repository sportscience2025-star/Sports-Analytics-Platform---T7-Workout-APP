## 1. What the prior attempt got wrong

### Issue 1: Leaking 'carico: undefined, tempo: undefined.' in 160+ Generated Program Exercises
- **Input:** Any program generated by WorkoutGeneratorAI containing warm-up (w_...), cardio (c_...), or clinical exercises without explicit load or 	empo fields.
- **Expected:** A clean description and specs object with valid defaults, and complete absence of 'undefined' or 'N/A'.
- **Actual:** Procedural string in uildSyntheticExercise produced: "Esercizio mirato al distretto Mobilità Articolare con parametri: 1 serie per 60s, carico: undefined, tempo: undefined.". In a multi-profile test across 6 diverse programs, 160 out of 335 exercises leaked undefined.
- **Root cause:** progEx.specs was assigned directly to specs without merging defaults, and string concatenation directly interpolated specs.load and specs.tempo without validation.

### Issue 2: Shallow Verification in Test Suite (	est_exercise_detail_resolver.js)
- **Input:** ssertNoUndefinedOrNA(res) in test suite.
- **Expected:** Verification that strings do not contain "undefined" or "N/A".
- **Actual:** Test utility checked if (obj === 'undefined' || obj === 'N/A') (exact match only). Because "carico: undefined..." is a compound string, it passed silently, concealing the defect.
- **Root cause:** Inadequate assertion predicate in the prior test suite.

### Issue 3: Missing Motor Pattern Errors for Upper Push and Upper Pull
- **Input:** Upper body synthetic exercises (push-ups, chin-ups, bench variations, shoulder activations).
- **Expected:** Biomechanical errors with error, why, ix specific to upper pushing and pulling patterns.
- **Actual:** Only a single generic error ("Esecuzione accelerata e incontrollata") was returned.
- **Root cause:** Omission of PATTERN_UPPER_PUSH and PATTERN_UPPER_PULL cases in generateErrors.

### Issue 4: Phase Disambiguation Blindness in Multi-Phase Programs
- **Input:** Clicking an exercise in Phase 2 or Phase 3 of a periodized program when the exercise also exists in Phase 1.
- **Expected:** Resolving the load, sets, and notes of the specific phase being viewed.
- **Actual:** Always resolved to Phase 1's specifications because indExerciseInProgram scanned phases linearly without phase awareness.
- **Root cause:** Buttons in wizard.js omitted data-phase-id, and indExerciseInProgram did not prioritize active phase.

### Issue 5: Raw Unescaped Exercise Names in HTML Attributes
- **Input:** Exercise names containing double quotes (e.g. 2" in buca or "Arnold Press").
- **Expected:** Valid HTML attribute values without syntax corruption.
- **Actual:** data-ex-name="" broke HTML attribute boundaries.
- **Root cause:** Omission of window.escapeHTML.
