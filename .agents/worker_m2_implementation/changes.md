# Implementation Changes Log

## Summary of Modifications

### 1. Requirement R1: Encoder ID Auto-Parsing (`js/parser.js`)
- **`isEncodedId(name)`**: Updated regular expression from `/^.+_[a-z0-9]{6,}$/i` to `/^.+_[a-z0-9]{3,}$/i` to support shorter hash tokens generated by hardware encoders.
- **`extractReadableName(encodedId)`**: Refactored extraction logic to split on `_`. When multiple parts or hash tokens are present (e.g. `Tommaso_mhkuhpch00134m` or `Mario_Rossi_mhkuhpch00134m`), the preceding parts are extracted and joined into Title Case (`Tommaso`, `Mario Rossi`). Added generic athlete check via `isGenericAthlete()` to gracefully fall back to `"Encoder"` if no valid name is found.
- **`isGenericAthlete(name)`**: Abstracted into an IIFE scope function shared by `extractReadableName` and `window.DataParser.isGenericAthlete`.

### 2. Requirement R2: Force-Velocity Imbalance / Sfv Fix
- **`js/physics-engine.js`**:
  - In `quadraticRegressionVBT`, guarded `sfvp` calculation with `Number.isFinite(sfvp)`.
  - Added calculation for `fvBias` in `quadraticRegressionVBT` matching the biomechanical interpretation of `sfvp`.
  - Included `fvBias` in the returned object of `quadraticRegressionVBT`.
- **`js/data-analysis.js`**:
  - In `renderVBTDashboard`, defined `sfvpVal` (guarded with `Number.isFinite`) and `sfvpDisplay` pure numerical string (e.g., `+15.2%`).
  - Replaced all calls to `${reg.fvBias}` on the Sfvp badge and qualitative analysis box with `${sfvpDisplay}`.
  - Ensured no extra descriptive text is rendered on the Sfvp badge and prevented `"undefined"` string rendering on the UI under any condition.

### 3. Service Worker Cache Bump (`sw.js`)
- Bumped `CACHE_NAME` constant from `'t7-workout-v17'` to `'t7-workout-v18'` to force browser cache invalidation.
